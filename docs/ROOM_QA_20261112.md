# SURA CHAT — Room redesign and QA, 12 November 2026

## Implemented on `feature/sura-chat-staging-source-20261112`

- **Separate native Android room screen**: royal navy/purple/gold visuals, responsive header, pinned announcement and stable 4-column seat stage.
- **1-tap room join** from the room list. Guard against duplicate join submissions; guard against duplicate room creation.
- **Seat display**: 4/8/12/16 supported, locked/free/occupied states, public ID and nickname always rendered, no automatic owner seat, profile avatar image updates keyed by `avatar_key`.
- **Stage stability**: compare server seat JSON before rendering; no full-screen rebuild on polling. Stage scroll area and message box separated so new chat lines do not push seat rows.
- **Chat**: incremental requests by message ID, bounded messages in a fixed-height panel, text composer, sends confirmed by server.
- **Owner & moderator**: edit room name, announcement, capacity and room lock; assign/revoke room moderators; list room members and bans; unblock by user ID. Occupied seat popup supports profile, private chat, and server-authorized kick/block. Long-press on free seat can lock/unlock. Server permissions are always authoritative.
- **Navigation**: dedicated room back arrow and device back use the server leave route to clear seat/presence; main-screen back has an actual exit confirmation instead of endlessly refreshing the room list.
- **Gift catalog**: read-only preview (no charge, no misleading fake send).
- **Voice button**: explicitly says **NOT CONNECTED** until the RealtimeKit Android SDK is implemented and device-tested.

## Evidence and limits

- GitHub Actions builds `assembleDebug` from Android Java sources and uploads a debug APK artifact.
- Node regression tests cover unauthenticated room and moderator actions, invalid room filters, and basic room UI contracts. These are not end-to-end device tests.
- The staging Cloudflare Worker and D1 database were **not overwritten or migrated** by this set of changes.
- One initial read of SURA staging D1 on 12 November showed 0 active rooms, 0 active room memberships and 0 occupied seats; there were no live rooms available for observing concurrent seat interactions.
- The RealtimeKit staging Worker has RTC-related bindings, but this Android prototype has no RTC join/mute/speaker implementation. **No claim of live audio functionality.**
- Google Play signed release AAB, billing, real coin transfers and video gifts are **not implemented here**.

## Manual acceptance testing still required

1. Two Android devices, real accounts and real microphone permissions.
2. Seat competition: two users tap the same free seat simultaneously; only one succeeds.
3. Owner room management, admin delegation, removal and role enforcement (403 for regular users).
4. Room exit, reconnect, app termination during background/poor network. **Abrupt process termination does not yet trigger server-side heartbeat/TTL cleanup**, so stale memberships are a known blocker.
5. Join message visibility: no messages from before the current join; pinned announcement remains.
6. Avatar sync after profile change, different image sizes and bandwidth-limited network.
7. RealtimeKit Voice-type presets for listener/speaker, foreground service, mute/stand/revoke and two-device audio monitoring.
8. Accessibility: screen readers, keyboard/small screens, landscape, large fonts, Arabic layouts.
9. Full error-handling for 401, 403, 409, 429, 503 and offline transitions.
10. Re-run Android build, static checks and device tests after every future production change.

## Priority next steps

1. Integrate RealtimeKit native Android Core SDK and verify voice with two physical devices, including background audio and mic permissions.
2. Add backend heartbeat + stale membership cleanup with additive D1 migration and tests; keep room presence and seat occupancy correct under crashes.
3. Implement secure user block/report and full admin moderation, then gifts/CP and ledger workflows in separate audited stages.

The code changes are a **staging feature branch** in draft PR #1. Do not treat this as production or a Google Play release.
